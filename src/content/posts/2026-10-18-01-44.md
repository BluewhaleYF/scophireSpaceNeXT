对于羊稍早在开发群聊中关于修改 Solian 客户端登录方式的方案，我在认真评估后，表示**强烈的反对**。

我对该方案的粗浅理解是：放弃原生登录体验，转而在登录界面打开外部网页（Webview 或跳转默认浏览器），在 `id.solian.app` 中完成登录后，返回令牌给客户端。

我非常理解羊作为主要开发者在维护和风控上的痛点，也深切体会同为高中生时间精力的紧张。目前 Solar Network 生态下存在 Solian、FloatIsland、Solwatt、Persynth、Maidkit 等各种各样的客户端，要统一维护确实是一项巨大的工程。

**但我认为，针对不同的客户端，登录方案应该进行差异化对待：**
FloatIsland 本身就是 Web 端，没有影响；在 Solwatt、Persynth、Maidkit 这类附属客户端上，为了兼顾开发效率，我认可并接受使用 Webview 进行登录。**但 Solian 作为 Solar Network 最核心的入口，必须最大程度保留原生体验。** 这也就意味着，我恳请您只为 Solian 这一个核心应用维护原生登录 UI，这绝对是值得的。全盘 Web 化的登录方式在 Solian 上明显弊大于利：

#### 真实的用户场景与痛点
众所周知，Solar Network 的用户绝大多数是位于中国大陆的初高中学生（我也不例外），我们的使用环境存在以下真实特征：
1. **公用设备与冰点还原**：很多学校机房电脑有冰点还原，登录状态无法持久化，每天都要从头登录。这让“登录”从几个月一次的偶尔操作，变成了直接影响每日使用体验的高频动作，极其考验登录的便捷性。
2. **网络限制与加载缓慢**：受限于国内网络环境、服务器位置及资源引用，不使用加速器时，网页端 Solian 的体验非常缓慢。实操中，能成功进入 Solian 已经非常费时，若还要额外等待外部网页加载认证，势必进一步拉长登录时长 。
3. **老旧设备兼容性**：很多用户仍在使用旧款手机，WebView 版本落后。先前签到系统引入 hCaptcha 验证时，就已经引发了大量麻烦；如果把登录这种核心功能强依赖 WebView，无疑是对老设备用户的二次打击。

#### 技术层面
出于风控和维护的考量可以理解，但在技术实现上，全盘 Web 化并非唯一解：
1. **验证码不需要 WebView**：极验（Geetest）等验证器拥有非常成熟的 Android / iOS / Flutter 原生 SDK，内置到客户端是行业标准做法，无需强迫用户开 WebView。
2. **风控与原生 UI 不冲突**：风控逻辑完全可以通过服务端动态下发。常规情况走原生登录，风险高时由服务端下发指令，客户端拉起原生极验 SDK 验证即可。
3. **后台轮询（Polling）极度原始且致命**：您提出“客户端只是 polling，可以用浏览器”。但移动端一旦跳转到外部浏览器，客户端切到后台极易被系统杀掉进程，导致轮询中断，用户切回来发现根本没登录上。这种做法既不优雅，也不稳定。
4. **违背 OAuth 行业规范**：RFC 8252 规范明令禁止在原生 App 内嵌 WebView 进行 OAuth 授权（Google 等甚至会封禁此类请求）。如果非要做外部授权，正确做法是系统浏览器 + PKCE + Deep Link 深度回调，而不是粗暴地后台轮询。

#### 产品理念与用户体验
> If it could save a person's life, could you find a way to save ten seconds off the boot time? If there were five million people using the Mac, and it took ten seconds extra to turn it on every day...


这是 Steve Jobs 说服团队优化 Mac 开机速度时的一段话，现在我也想将这段思考送给羊。
**开发上节省的一小部分工作量，乘以用户基数，就是对用户极大的不负责任。** 为了自己少写几行原生接入代码，让所有用户每次登录都要多开网页、多忍受网络转圈，这不仅是**产品体验的降级**，更是把一人的方便建立在广大用户的时间损耗之上。虽然 Solar Network 目前 MAU 不大，但作为一个社区，用户是保持活力的根源。任何产品都要以人为本，严重牺牲用户体验去换取开发上微小的节省，是不值得的。

#### 最终诉求
我**不反对**底层统一使用 `id.solian.app` 的 OAuth 2.0 鉴权协议。我也**接受**在附属客户端上使用 Webview 登录。但我**坚决反对**在 Solian 这个核心 Flutter 应用内用 WebView 承载授权页面，更反对让用户跳出 App 去外部浏览器登录。

**具体落地建议：**
1. **保留 Solian 内的原生登录 UI 和账号设置面板。**
2. **用户输入账号密码后，直接调用接口发起 OAuth 鉴权，验证码必须使用极验原生 SDK 内置**，而非网页。
3. 如需展示第三方同意页面，请使用系统浏览器或 Custom Tabs 配合深度回调，不要在内嵌 WebView 里做。

App Store 版本目前没几个人用，不能作为牺牲主平台体验的借口。希望羊能尊重用户的真实生存环境，不要把 Solian 变成半残的网页套壳。作为贡献者，我愿意为项目做贡献，也请您守住原生应用的体验底线。
