# 结识 COSMIC

都说 2026 年是 Linux 桌面元年。虽然这个说法有争议，但从科技媒体对 Linux 的关注度和重视程度来看，确实有了很大变化。Linus Tech Tips（LTT）今年也做了相当多有关 Linux 的视频，可以明显感受到他们的态度从把 Linux 视为“极客的选择”，转变为认为它“确实值得尝试”。在他们的视频中，我注意到 Linus 选择了一个名叫 Pop!_OS 的发行版，其搭载的桌面环境也是我此前没听说过的 COSMIC。

粗略了解一番后，我被它的几个特点吸引住了：

- **优秀的外观**：UI 设计一流，简约现代中带着一丝恰到好处的炫酷，非常符合我对现代桌面环境的想象。

- **前卫的理念**：COSMIC 的核心组件主要使用以内存安全和高性能著称的 Rust 编写，而不是传统的 C/C++；显示栈也完全围绕 Wayland 设计，从合成器到上层组件都尽量避开了传统 X11 桌面的历史包袱。

- **完美的融合**：COSMIC 同时提供传统的堆叠式布局和自动平铺布局，让两种截然不同的工作方式在一个桌面环境中并存，只需切换开关就能快速切换。

![official image](https://raw.githubusercontent.com/BluewhaleYF/ScophireSpace-Files/refs/heads/main/Posts/6/COSMIC%20official%20demo.webp)

作为一个被 Hyprland / Niri 的配置复杂度劝退过的 Linux 用户，这简直是一个完美选项：不用啃文档、写配置，就能体验真正原生的 Wayland 平铺体验，还能拥有现代美观的图形界面，确实很吸引人。

于是我便在自己那台装着 CachyOS 的 2014 款 MacBook Pro 上安装体验了一番。本文主要分享我这两天体验下来的一些感想，不专业之处还请见谅。

# 惊鸿一瞥

COSMIC 已经进入 Arch Linux 的官方 extra 仓库，并以 package group 的形式提供，安装非常便捷，只需要一行命令：

```bash
sudo pacman -S cosmic
```

按提示选择要安装的组件即可完成安装。

登录 COSMIC 会话后，简单调整一下就能获得这样的视觉效果：

![desktop demo](https://raw.githubusercontent.com/BluewhaleYF/ScophireSpace-Files/refs/heads/main/Posts/6/tiling2.png)

整个桌面大量运用了半透明效果，配合 **Frosted Glass** 毛玻璃效果，却没有给人一种刻意炫技的感觉。启动器、通知中心以及面板上的各种弹出菜单，都采用了相同的设计语言，层层叠叠的窗口配合背景壁纸，很容易营造出一种十分通透的空间感。我第一眼看到时，脑海里甚至冒出了 OS X El Capitan 那个时代的印象，干净、克制，却又不显得单调。

浅色主题倒是让我有一点遗憾。按理说这种设计应该呈现出一种带着轻微模糊感的纯白质感，但目前默认配色略微偏灰，少了几分通透，多了一点沉闷，相比深色主题明显逊色一些。

活动窗口的高亮边框也是我最喜欢的细节之一。当前窗口会被一圈纯色边框轻轻勾勒出来，没有阴影，也没有复杂的特效，看起来反而格外干净。这种设计让我想起了自己 Hyprland 配置里的活动窗口边框，简单到几乎只有一圈描边，却一下子让整个桌面的气质变得很现代，窗口焦点也因此一目了然。

这套视觉效果如果放到 Hyprland 或 Niri 上，大概要花不少时间翻 Wiki、改配置，再不断调整模糊、透明度、动画曲线这些参数才能得到差不多的效果；COSMIC 则把常用的外观选项直接放进了图形设置里，安装完成后几乎不用继续折腾，只需要动几个滑块，就已经有很高的完成度。

整个设置界面的布局也很舒服，没有为了追求“高级感”把各种选项藏得很深，常用功能基本都能在两三次点击内找到。第一次接触 COSMIC，我几乎没有花什么时间适应它的设置逻辑。

这种开箱即用的体验，也让我第一次觉得，平铺桌面其实没有想象中那么难上手。

COSMIC 也没有把自己定位成一个纯粹的平铺桌面。它同时保留了平铺与堆叠两种工作方式，需要整理窗口的时候可以切换到平铺模式，平时也能继续按照传统桌面的习惯使用，两种模式之间的切换非常自然。

不过，当我真正开始把它当成日常桌面使用之后，这份惊艳很快就被现实拉了回来，其中最明显的问题，就是性能。

# 老机优化一般

即使关闭 **Frosted Glass** 等高级视觉效果，整个桌面在这台 Mac 上运行依然存在**明显卡顿**，连鼠标指针移动都会明显掉帧，已经影响到了正常操作。

虽说这台电脑比较老，但它在 GNOME 会话下还算流畅，因此有理由怀疑是 COSMIC 本身的优化问题。

当然，考虑到 COSMIC 1.5.0 虽已正式发布，但仍处于快速迭代和打磨阶段（截至本文发布时，1.5.0 就是最新稳定版），其合成器基于 Rust 和 Smithay、界面层基于 Rust 和 Iced（libcosmic），目前似乎还没有针对这块 Intel Haswell-ULT 老集显做好充分优化，倒也在意料之内。

想起几天前我在 KVM/QEMU 里装 Pop!_OS 虚拟机时，也遇到过类似的问题。我给虚拟机分配了 10 个 vCPU 和 8 GB 内存，界面依然卡顿严重，窗口移动时甚至会出现大面积撕裂，画面几乎被切得到处都是。不过，这也可能与 VirGL/SPICE 对 COSMIC 图形栈或 Iced 渲染路径的兼容性有关。

---

# 奇妙的小问题

相比整体性能，更让我摸不着头脑的是：**鼠标指针的卡顿是有条件的**。

在 COSMIC 桌面、设置等自带应用中，移动鼠标时掉帧十分明显；而一旦打开 **GTK 应用**，无论是移动还是悬停，都明显流畅许多，几乎恢复到了 GNOME 下的体验。

目前我还没有找到原因，只能做一些猜测。GTK 应用很可能走的是另一套已经比较成熟的渲染路径，而 COSMIC 自身基于 Iced 的渲染管线，对于 Intel Haswell 这一代老核显的优化仍然不够完善，因此两者在同一台机器上的流畅度出现了明显差异。

当然，这只是我根据现象做出的推测，并没有进一步分析渲染日志或 GPU Profiling。

# 试图挣扎优化

查了一些资料之后，我尝试开启了 Intel i915 驱动的两个特性。

```bash
sudo nano /etc/modprobe.d/i915.conf
```

写入：

```text
options i915 enable_psr=2 enable_fbc=1
```

其中：

- `enable_psr=2`：允许 PSR 最高到 PSR2（面板支持时；Haswell 上通常只会协商到 PSR1）
- `enable_fbc=1`：启用 Framebuffer Compression（FBC）

如果 i915 被打包进 initramfs，改完配置后还需要重建 initramfs（Arch/CachyOS 上通常是 `sudo mkinitcpio -P`）再重启，否则参数可能不会生效。

重启之后，卡顿问题**几乎没有改观**，随后放弃。

# 中文体验

COSMIC 中文本地化目前比较粗糙，系统界面中仍有大量文本没有翻译，已经完成翻译的字符串质量也不太稳定。默认安装没有针对东亚字体回退做优化，同一句话里可能同时出现多套字体，粗细、基线和字形风格都不统一，简体中文、繁体中文以及日韩字体混在一起时，观感尤其凌乱。

解决起来也不难，只需要在设置里把系统字体统一设置为 `Noto Sans CJK SC`（简体中文字体），就能获得不错的观感（如下图）。

![font demo](https://raw.githubusercontent.com/BluewhaleYF/ScophireSpace-Files/refs/heads/main/Posts/6/tiling.png)


好在 Fcitx5 的兼容性相当不错，候选框、输入状态切换和中文输入都能正常工作，暂时没有遇到明显异常。可惜 COSMIC 虽然已经支持自定义快捷键，却还没有提供 GNOME Tweaks 的 Additional Layout Options 那种键位映射入口，这对我的使用习惯影响挺大。

# 总结

短短两天的体验还不足以评价 COSMIC 的全部水平，但已经足够让我理解为什么它最近会受到这么多关注。至少在**交互设计和整体理念**上，它确实有不少让我眼前一亮的地方。

不过，至少在这台使用 Haswell 核显的老 MacBook Pro 上，它目前的**性能还无法满足日常使用需求**。鼠标指针和原生应用频繁掉帧，非整数缩放的选择也不够灵活，所以我最后还是切回了 GNOME，先保证基本的流畅度。

毕竟这是一个仍处于快速迭代阶段的 DE，打磨还需要时间。对 System76 后续的打磨保持乐观，毕竟交互理念和配置逻辑确实切中了我的日常需求，假以时日，COSMIC **完全有潜力成为我的主力 DE**。

COSMIC 目前暴露出来的问题，大多集中在性能优化、本地化和应用适配上，这些都需要后续版本继续打磨。我最初喜欢的那套交互思路和设计理念，也没有因为这些问题而失去吸引力。等性能和细节成熟一些之后，我很愿意再回来试一次。
